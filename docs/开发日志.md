## 2026-07-26 · GEX 分栏（第 1 个分栏）· 后端引擎跑通

### 已完成

**`backend/sources/cboe.py`** —— CBOE 延时期权数据源
- 基于 global-stock-data V2.0 已验证实现（过 Codex 三轮审计）
- `Contract` / `Chain` 用 frozen dataclass（不可变，符合项目 immutability 规范）
- 线程安全限流器、`DataNotAvailable` 与 `RuntimeError` 分离（配置/网络错误必须冒泡，不能伪装成"没数据"）
- DST 感知的 `et_today()`（硬编码 UTC-4 会让冬令时 0DTE 选错日期 —— global-stock-data v2.0.1 踩过）

**`backend/modules/bs.py`** —— Black-Scholes gamma
- 只用标准库，不引 scipy（保持零重依赖）
- 退化情况（到期/零 IV/无效价）返回 0 而非抛异常 —— 真实期权链里天天出现

**`backend/modules/greeks.py`** —— GEX 计算
- `contract_gex()` 单合约：`gamma × OI × 100 × spot² × 0.01`
- `total_gex_at()` 假设股价下的总 GEX（**用 BS 重算 gamma**）
- `_find_gamma_flip()` 扫描 + 二分求零点
- `compute()` 出完整画像：total / by_strike / by_expiry / flip / call wall / put wall

### 实测结果（SPY 2026-07-26）

```
spot        738.93
总 GEX      -4.352 B$/1%   → negative gamma（做市商对冲会放大波动）
Gamma Flip  747.13         ← 现价在 flip 之下
Call Wall   740.0
Put Wall    740.0
```

**双重校验通过**：
1. 模块结果与手工套 gex-tracker 公式复算 **完全一致**（-4.352168 B）
2. flip 点校验：$739.66→−4.06B / $747.13→−0.003B / $754.60→+2.91B **确实是变号零点**

### ⚠️ 关键设计决定（别改坏）

1. **Gamma Flip 必须用 BS 重算 gamma**，不能复用 CBOE 给的 gamma。
   CBOE 的 gamma 是**当前股价下**的值；flip 要问"如果股价变成 X"，而 gamma 随股价剧烈变化（ATM 最高、两端趋零）。
   第一版用"累计 net_gex 找符号翻转"的简化法，结果返回 `None`（因为全程负）——**那是错的近似**，已弃用。

2. **做市商持仓方向是假设，不是事实。**
   业界通用（SqueezeMetrics/gex-tracker）假设「call 记正、put 记负」。本模块用 `convention` 参数显式化，并在 `to_dict()` 的 meta 里输出这句话。**不要把它藏进代码当真理。**

3. **找不到 flip 就返回 None**，不硬凑数字。很多标的在合理区间内确实不翻转。

### ⚠️ Codex 审计：九轮、抓出 13 个真问题

**按类型归纳（这些都是「只看代码发现不了」的）：**

| # | 问题 | 教训 |
|---|---|---|
| 1 | 前端「全部」档主端点用全链、curve 端点默认 7 天 | **两个端点必须同口径**，否则曲线不在标注的 flip 处穿零 |
| 2 | gamma flip 取「最低价交叉」而非「离现价最近」 | 多交叉是常态，取第一个会报出无意义的远端点 |
| 3 | 无 `requirements.txt` | 干净 clone 跑不起来 = 自部署承诺落空 |
| 4 | curve 写死 ±15% strike，主端点用调用方的 strike_pct | 同上，口径必须一致 |
| 5 | flip 落在曲线范围外时，标线被画到图表边缘 | **把边界谎报成穿零点** |
| 6 | **403 被归成 DataNotAvailable** | ⭐ 我自己写在模块文档里的原则被自己违反：限流/封禁必须冒泡，不能伪装成「没数据」 |
| 7 | `r.json()` 在 try 外，上游返 HTML 时抛未捕获异常 | 错误边界要包住解析 |
| 8 | MCP 两工具默认口径不一致 | AI 同时调两个会拿到对不上的结果 |
| 9 | MCP 协议版本原样回显客户端请求 | 等于声称支持自己没实现的语义 |
| 10 | curve 请求失败被静默吞成空数组 | **静默失败**：显示空图却报成功 |
| 11 | x 轴用类目轴、价格四舍五入到整数 | ⭐ **只测了 SPY($738) 没测低价股**：福特 $14.36 的 61 个采样价四舍五入后只剩 **2 个**不同标签 |
| 12 | 缓存无锁，前端两个并行请求各拉一次 CBOE | 浪费配额 + **两份不同快照** |
| 13 | 零敞口报成 negative；改完又漏改 MCP summary | 边界值要有 neutral；**加了状态就要全链路跟上** |

### ⭐ 三条可复用的教训

1. **「同一份数据的两个视图，必须走同一套过滤条件」** —— 13 个问题里有 4 个是这类（1/4/8/12）。
2. **异常分类必须正向识别** —— 403 当成「没数据」，会让"被封 IP"永远查不出来。这条与 global-stock-data v2.0.1 的根因完全一致，**同一个错我犯了两次**。
3. **测试要覆盖参数空间的边界**，不只是主力标的 —— 低价股那个 bug 只有测 $14 的票才暴露。
